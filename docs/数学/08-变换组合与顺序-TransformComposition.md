## 教材核心公式

列向量约定下，矩阵组合满足：

```text
(A·B)·p = A·(B·p)
```

因此最靠近向量的右侧矩阵最先作用。若想“先旋转 `R`，再平移 `T`”，组合矩阵必须写成：

```text
world = T·R·local
```

矩阵乘法通常不可交换：

```text
T·R ≠ R·T
```

## 标准数值推导

已知局部尖端 `p=(1,0,0)`、平移 `t=(10,0,0)`，Y 轴 `+90°` 把 `(x,0,0)` 变为 `(0,0,-x)`。

错误顺序 `R·T·p`：

```text
T·p = (11,0,0)
R·(11,0,0) = (0,0,-11)
```

旋转作用到了“局部点 + 世界平移量”，所以角色位置 `(10,0,0)` 也绕世界原点旋转，表现为公转。

正确顺序 `T·R·p`：

```text
R·p = (0,0,-1)
T·(0,0,-1) = (10,0,-1)
```

只有局部偏移绕角色原点旋转，随后整体搬到角色世界位置，表现为自转。

对局部原点 `(0,0,0)` 的检查更直接：

```text
R·T·0 = (0,0,-10)  // 错：角色位置绕世界原点跑了
T·R·0 = (10,0,0)   // 对：角色原点保持在世界位置
```

绕任意世界枢轴 `c` 旋转时，可推广为：

```text
T(c) · R · T(-c) · p
```

从右往左读：先把枢轴移到原点，再旋转，最后移回去。

## 游戏工程翻译

- 模型局部顶点先吃旋转/缩放，再吃物体世界平移：`T·R·S·p`。
- 把 `T` 放到 `R` 右侧，平移量也会被旋转，物体看起来绕原点或父节点公转。
- Unity API 可能在存储布局和乘法写法上有所不同；不要死记左右，先确认向量约定，再用一个具体点验证。

## 1. 四个数不是四个旋转角

记 `q=(x,y,z,w)=(u,w)`，u 是三个虚部分量，w 是标量。单位旋转四元数满足：

```text
x² + y² + z² + w² = 1
```

四个分量受一个约束，因此仍描述三个旋转自由度。xyz 不是 forward，也不是 yaw/pitch/roll。四元数保存完整朝向，可以同时决定 right、up、forward；仅有 forward 无法确定翻滚。

### TODO 11.1：轴角 → 单位四元数

设非零旋转轴为 a，单位轴 n=a/|a|，角度为 θ：

```text
h = angleDegrees * π / 180 / 2
q = (nx*sin(h), ny*sin(h), nz*sin(h), cos(h))
Identity = (0,0,0,1)
```

sin²(h)+cos²(h)=1，因此单位轴生成单位四元数。例：Y+90° 对应 `(0,√0.5,0,√0.5)`；输入轴 `(0,3,0)` 必须得到同样结果。本节输入保证有限、轴非零，不要求零轴异常处理。

为什么是半角？先看绕 Z 旋转 X 方向：用后面的 `q·p·q*` 展开，会得到 `(cos²h−sin²h, 2sin(h)cos(h), 0)`，即 `(cos(2h),sin(2h),0)`。实际旋转角是 2h，所以创建时要取 θ/2。

## 2. 四元数乘法不是分量相乘

### TODO 11.2：Hamilton 积

设左侧为 a，右侧为 b：

```text
x = aw*bx + ax*bw + ay*bz - az*by
y = aw*by - ax*bz + ay*bw + az*bx
z = aw*bz + ax*by - ay*bx + az*bw
w = aw*bw - ax*bx - ay*by - az*bz
```

其紧凑形式是 `(aw*bv + bw*av + av×bv, aw*bw − av·bv)`；叉积换序会变号，所以乘法不交换。代数基础 `i*j=k`，而 `j*i=-k`，不能用加法合并旋转。

Multiply 支持一般四元数，不能在内部自动归一化：旋转向量时，中间的纯四元数并非单位四元数。单位旋转四元数相乘在精确数学中仍为单位四元数；长期累积的浮点漂移另行讨论。

## 3. 如何旋转一个方向

### TODO 11.3：TransformDirection

```text
p = (direction.X, direction.Y, direction.Z, 0)
q* = (-q.X, -q.Y, -q.Z, q.W)       // 共轭
rotated = q * p * q*
返回 rotated 的 xyz
```

只有 q 是单位四元数时，q* 才等于逆。输入方向无需归一化：旋转必须保留长度。这里的 p.w=0 是纯四元数编码，不是把四元数当成齐次坐标。

q 与 -q 表示同一旋转，因为 `(-q)*p*(-q*) = q*p*q*`。所以四元数分量不相等，不代表朝向不同；判断旋转行为可以比较变换后的基向量。创建函数测试检查指定轴角公式的分量，场景测试检查实际方向。

## 4. 错误使用：绕世界轴还是自身轴？

打开 `Homework/数学/11-四元数定义与运算/QuaternionLesson.cs` 的 `ShipRotation`。飞船已绕 Y 转 90°，现在要求绕飞船自身 X 轴追加 +90°。现有代码故意将增量放错一侧。

记当前局部到世界朝向为 q，增量为 d：

- 局部轴增量：`qNew = q*d`。对局部向量 v，是先在局部施加 d，再由 q 转到世界。
- 世界轴增量：`qNew = d*q`。先得到原来的世界方向，再在世界施加 d。

这与矩阵组合一致；“右边先作用”说的是向量映射，不代表游戏时间倒流。时间上追加一个自身轴增量，仍可以右乘。

本例正确结果：forward 为 -Y，right 为 -Z。错误顺序则得到 forward 为 +X、right 为 +Y。不要只在初始朝向测试，因为此时 q=Identity，两种顺序可能都通过。

四元数没有欧拉角那样的参数奇异点，但不会自动修好控制逻辑。如果每帧仍累加 yaw/pitch/roll，再转成四元数，欧拉控制的问题依然可能保留。本节直接保存四元数朝向，并用轴角增量更新。

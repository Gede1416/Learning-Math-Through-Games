## 1. 什么是AABB

教材：《3D Math Primer》作者在线版[附录A.17](https://gamemath.com/book/geomtests.html)关于两AABB相交的核心说明是：

> We simply check for overlapping extents on each dimension independently.

即分别检查各维度的范围重叠。AABB是Axis-Aligned Bounding Box，轴对齐包围盒，三组边分别平行所在坐标空间的X、Y、Z轴。本课统一世界空间，+X右、+Y上、+Z前；两盒必须在同一坐标空间才能直接比较。

盒子由Min与Max两个角点描述，表示三个区间的笛卡尔积：

```text
X: [Min.X, Max.X]
Y: [Min.Y, Max.Y]
Z: [Min.Z, Max.Z]
```

Min不是离原点最近的角，而是各坐标分量的最小值；Max同理。负坐标照常比较，不要取绝对值。

本节约定每轴Min<=Max，输入有限，允许某轴零尺寸。边界也属于盒子：点在表面算包含，两盒接触面、边或角都算相交。教材A.17示例用>=/<=排除边界接触，表示更严格的重叠；本课触发器采用闭区间，必须相应调整比较符号。这个差别来自接口契约，不是坐标系不同。

公共类型位于`MathLibrary/Aabb.cs`，命名空间`StudyNotes.MathLibrary.Geometry`，复用现有Vector3。数据结构已提供，下面3个算法由你实现。不要求自动修复颠倒的Min/Max，也不新增通用碰撞框架。

## 2. TODO 15.1 中心与半尺寸创建

方法`CreateFromCenterAndHalfExtents(center,halfExtents)`，halfExtents各分量非负：

```text
Min = center - halfExtents
Max = center + halfExtents
完整尺寸 = 2 * halfExtents
```

例如拾取区域中心(5,-2,10)，半尺寸(1,2,3)，Min=(4,-4,7)，Max=(6,0,13)，完整宽高深是(2,4,6)。传完整尺寸代替半尺寸会把范围扩大一倍。

halfExtents=0时盒子退化成一个点，Min=Max=center，仍符合本课契约。创建函数不要归一化半尺寸；每轴长度是范围信息。

## 3. TODO 15.2 点包含

方法`ContainsPoint(point)`。对每个轴检查该坐标处于闭区间：

```text
Min.X <= point.X <= Max.X
Min.Y <= point.Y <= Max.Y
Min.Z <= point.Z <= Max.Z
```

三组条件必须全部满足。C#不能写数学的连续不等式，要拆成两次比较；把三个轴结果用AND连接，不能用OR。

角色脚底落在范围里不代表身体都在范围里；同样，只测试身体中心也不能代表身体与区域的相交情况。点包含与盒体相交是两个不同需求。

## 4. TODO 15.3 两盒相交

先看一维。两个闭区间A=[aMin,aMax]、B=[bMin,bMax]分离的条件：

```text
aMax < bMin  或  bMax < aMin
```

否则有交集，等价于：

```text
aMin <= bMax  且  bMin <= aMax
```

推广到三维：任意一个轴分离就返回false；三个轴都重叠才返回true。可以逐轴提前返回，也可以计算三轴条件并用AND连接，任选一种即可。

例如A的三轴区间都是[0,2]，B的X/Z也是[0,2]，但Y为[3,4]。虽然X、Z都重叠，两个盒仍完全分离。因此“至少一个轴重叠”不够。

为什么三个轴都重叠就足够？每轴可选一个公共坐标，把三个坐标组合成一点，它就同时位于两个轴对齐盒中。这依赖轴对齐，不能直接套到旋转后的OBB；下一课再讨论任意朝向盒。

不要用“某个角点在另一个盒内”代替区间判断。横向长薄盒与纵向长薄盒可以十字相交，同时所有角点都在对方外部。包含关系、部分重叠和边界接触也都应对称：A.Intersects(B)与B.Intersects(A)一致。

## 5. TODO 15.4 拾取区域漏触发

文件：`Homework/数学/15-AABB相交与检测/AabbLesson.cs`，`PickupTrigger.ShouldTrigger`。

需求：玩家盒与拾取盒有任意交集，包含边界接触，就触发。现有代码只取玩家中心，检查中心是否进入区域。

```text
拾取区X范围: [-1,1]
玩家X范围:   [0.8,2.8]
玩家中心X:  1.8
```

玩家与区域的X交集是[0.8,1]，Y、Z也重叠，身体边缘已进入；中心1.8却在外，旧代码会漏报。修正时使用你写的盒体相交工具，不必重写另一套区间公式。

另一个反例：大玩家盒完全包住位于侧边的小拾取区，玩家中心可能仍不在小区域里。只交换中心点测试方向不能修好所有情形。

本节触发区域与玩家都明确建模为盒子，所以盒相交就是本例的最终规则。ShouldTrigger返回当前时刻是否重叠，持续重叠时可连续返回true，不代表只触发一次进入事件；本节不实现事件状态。若盒只是复杂模型的包围盒，重叠只意味着有必要继续精确检测：空隙可能造成候选误报。反之，两个有效包围盒若分离，被包住的模型也不可能相交。

每次比较只需检查三个轴区间，适合作为便宜的初筛。但本节是离散时刻的检测，不计算碰撞发生时间；高速角色若一帧从区域左侧跳到右侧，两个时刻都可能不重叠，仍可能漏掉中途经过，需要后续连续检测。
